# RMI_Surface integration

## Scope

The add-on applies the RMI_Surface Blender material path only to StaticMeshes
loaded directly from mounted Rebirth packages. That includes StaticMesh actors
created by the package UMAP importer, because they use the same
`PackageStaticMeshResolver`. Skeletal meshes, loose MEC UMAPs, JSON imports,
and non-RMI material instances keep their existing material behavior.

For each RMI material instance, the package bridge reads its cooked parent and
parameter arrays. The parent selects the exact `RMI_Surface_*` switch variant;
texture parameters populate the corresponding packed DDS image slots; matching
Unreal vector/color parameters replace the image node in that slot with a
Blender RGB constant node. Named Unreal renderer sRGB constants such as
`FFFFFFFF_sRGB` are likewise decoded directly to an RGB constant node rather
than exported as a DDS. Scalar parameter overrides are copied to the
material properties where the port exposes the same name.

## Bridge contract

`bridge/Program.cs` provides the package-server `material` request. Its
mapping-independent property conversion returns the cooked MaterialInstance
property tags instead of depending on unstable C# material export classes; the
installed `.usmap` supplies the Rebirth-specific parameter struct layouts.

## DetailCoverage (fur cards)

`DetailCoverage_` now creates a `DetailCoverage` non-color slot and samples it
on the third UV set (Blender UV index `2`), matching the EID 10082 base-pass
sample. The baked Detail textures use the same third UV set, while `Detail`
itself is the material-placement mask on the second set; the hair flow map
also remains on the second set. Its neutral value is `1`, so variants without
the switch retain their ordinary Coverage behavior. When enabled, it is
combined with `Coverage` before the coverage/alpha node; this makes
`PC0004_00_Fur_A` drive the fur-card cutout for `PC0004_00_Body_Fur` while
retaining the material's base coverage map.

The game shader's exact coverage shaping also involves its engine dither and
coverage-identifier context. Blender uses the deterministic product of the two
coverage maps before its existing coverage mode, which preserves the authored
fur mask without claiming an exact reproduction of UE's temporal alpha test.

For a material carrying `DetailCoverage_`, the Blender alpha path also subtracts
the Light Path `Is Shadow Ray` value. This deliberately disables card shadows
for that fur-family path: a practical viewport/render approximation for assets
authored for the game's non-ray-traced shadowing, rather than a physical hair
model.

The master shader also subtracts Geometry `Backfacing` from final alpha,
clamped to zero. This gives all imported RMI surfaces shader-level backface
culling in Cycles as well as Eevee, without relying on a render-engine-specific
material setting.

## DetailNormal intensity

The detail layer scales the unpacked `DetailNormal` tangent xy by a new
`Detail Normal Strength` material custom property and renormalizes before any
of the three blend paths (additive slerp, chained, RNM) consume it -- the same
shaping a Blender Normal Map node's Strength applies. The property defaults to
`0.5`, so imports now carry half the authored detail-normal intensity; set it
to `1.0` for the authored map, or `0.0` to drop the detail normal while keeping
the detail colour, roughness, and occlusion.

The character/detail slerp path first interpolates the *detail perturbation*
from the flat tangent normal and then composes it over the base with RNM. This
makes a neutral detail texel `(0, 0, 1)` an identity at every mask and strength
value; it can never soften the base normal simply because the detail layer is
enabled.

It is a separate control from the layer's `Detail Mask` gate, which stays the
material's authored placement mask. Variant trimming retires the property with
the rest of the detail machinery when a variant carries no detail-role switch.
